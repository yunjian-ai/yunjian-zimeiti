# 成品卡：问清一次，下一条就交成品

> 给人看：主人要的是能发的东西，不是过程。执笔问清楚要做什么（最多问一轮），下一条回复就交排好版、配好图的成品；中间的拆解、检查都在后台做，结果记在「自查记录」里，主人想看再看。
> 给 AI：写稿、仿写、改稿的技能交东西都照这张；和技能里「交稿」一节冲突时，以这张为准。主人说「一步步来」「先给我骨架」「先看初稿」，才按技能原来的分步走。

## 1. 需求最多问一轮
- 开工只问**决定做什么**的那一个问题，给 2～4 个选项、第一项标「推荐」；作者档案里有的、从料里看得出的不问。
- 主人回「你定」「照你推荐的」「都行」：按推荐项走，不再问第二个。
- 只有缺了就没法写的，才在这一轮一起问（一次最多 3 个）：主人一条真事都没给、又要写主人自己的经历；带货缺价格、缺商品信息。别的缺口都不是停点（见第 3 节）。
- 这一问之后的下一条回复，就是第 2 节的成品。要做好几分钟的，先回一句「大概 N 分钟，好了发你」，不报过程。

## 2. 交什么
中间各步（清点料、定角度、搭骨架、写、深改、配图、平台版、自检）在一条回复里一口气做完，不停下来问「要不要接着深改」「要不要配图」。

**东西一律当附件发，正文不铺进聊天。** 主人第一眼要看到的是排好版、带图的成品，不然没法判断：
1. **长文、图文默认交两个附件（不用问）**：
   - **排好版的彩色网页（主看这个）**：用同目录 `长文排版.py` 把写作稿转成网页——钩子、论点、证据各有颜色，==黄底== 重点、红字数字、★ 💡 ⚠️ 提示框、收藏件、两级编号全套都在；图片位写上图片文件名（「👇【图】说明｜图1.jpg」，图放在稿子同一个文件夹），图就嵌进网页，单发这一个文件点开就是排好版、配好图的成品。网页上有「写作视图」「发布视图」两个按钮。md 显示不了颜色和 `==` 高亮（Grok Bot 实测 `==…==` 原样露出来），所以要让主人看排版，交网页。
   - **发布版 md（方便改字、复制）**：同一次运行旁边那份「-发布版.md」，`==` 已换成粗体、粗体标记不贴中文标点、图片写成 `![说明](图1.jpg)`；交之前把图片转成内嵌（`![说明](data:image/jpeg;base64,…)`），不留外部路径。
   - 两个文件都控制在 1 MB 以内：图片先压成宽 1080 以内的 jpg（Grok Bot 实测 1.4 MB 的 md 第一次点开「无法读取文件」，723 kB 的一次就开）。发之前自己点开看一遍：图都在、颜色在、没有原样露出的 `==`、`**`。
2. **也写进飞书**（作者档案「成品交到」写了飞书，或主人说「放飞书」）：环境里有飞书命令行（`lark-cli`，已登录）就在成品文件夹里建一份飞书版 md，图片写成 `![说明](@./图片文件名.png)`（飞书不收 base64 图），运行 `lark-cli docs +create --as user --doc-format markdown --title "<标题>" --content @飞书版.md`（档案里有飞书文件夹就加 `--parent-token <文件夹>`），把文档链接放进聊天；建完读回来看一眼图都在。环境里没有飞书工具：照常交 md，聊天里一句「这里没接飞书，接上以后我能直接写进去」。
3. **主人要了才出**：原图 zip（要自己排版、换图时）、长图（发朋友圈、手机转发时）。主人没要就不发 zip，别多塞文件。
主人在聊天里看到的是两个文件卡片（写了飞书再加一个链接），加几行说明。**提到的文件都要发出来**：聊天里不许出现「在 /workspace/… 里」「文件夹里有」这种让主人自己去找的话，要么发附件，要么不提。

| 形式 | 附件 | 聊天里只放（≤ 8 行） |
|---|---|---|
| 长文、图文 | 彩色排版网页（图片内嵌）＋发布版 md；「自查记录」另存在成品文件夹，主人要看再发 | 照这个样子，四小段：①**第一句写明「这是排好版、配好图的成品，点开上面的网页就能看；md 是纯文字版，方便改」**，再说配了几张图 ②标题 ③要知道的事最多 3 条 ④有「可以补的」再加最多 3 条。下面贴封面一张预览。**不贴正文、小标题、出处、案例列表** |
| 口播 | **提词卡彩色网页（`提词卡.py` 出的 html）一定当附件发**，封面图一起发 | 稿子本身（主人要对着念、要复制）＋一行时长；要注意的最多 3 条；最后一句「彩色提词卡在上面的网页里，点开就能对着念」。聊天里显示不了 `==…==` 高亮，贴进聊天的那份把 `==重点==` 换成行首 🔸 加 **粗体**，`**重读**` 照旧；带 `==` 的原稿留给提词卡和检查脚本 |
| 选题 | 3～5 个选题，每个一句为什么、配什么收藏件 | 选题本身，推荐 1 个 |

- **配图默认自己出**：按作者档案「配图」一项——「自己出」（默认）：环境能出图就出图卡；出不了就给每张图的提示词＋尺寸；「只给提示词」：只给提示词；「不要」：不配。规矩照 pen-cover。
- 只有这个环境真发不了附件（试过发不出去），才把成品整篇贴在聊天里，`自查记录` 放最后、标题写「自查记录（不用看）」；不许只说「文件在 /workspace/… 里」让主人自己去找。
- 平台：作者档案里第一个平台出发布版；主人点了平台就按主人的；别的平台版本主人要了再出（pen-platforms）。
- 聊天正文（口播不算稿子本身，预览图不算）不超过 8 行；长文的正文一句都不进聊天。

## 3. 【问】不是停点
- 缺主人本人的感受、经历、看法的地方：**删掉，前后接通顺**，成品照样交；不替主人编。
- 删掉的那几处里，最能让稿子更像主人的挑最多 3 条，放在聊天末尾：「想更像你，可以补这几句（不补也能发）：①…」。主人补了，改进去重交一版。
- 成品正文里不留【问】。【推算】照样写出算式，放进 「自查记录」文件，聊天里提一句请主人确认。
- 带货的价格、商品卖点缺了：照第 1 节先问，不交带空格的成品。

## 4. 检查照做，不展示
- 出处表（每句出自哪条料）、`check_pen.py`（硬错改到零、排版和说人话那几类清零）、仿写的原创度（和原稿连续 15 字以上相同 0 处）、违规词和导流、图上数字和正文一致——全照各技能原来的要求做，结果写进 「自查记录」文件，「机械检查」照抄脚本第一行和最后一行。
- 聊天里只写一行结果：「检查过了：事实都有出处、原创度、违规词都过」；有过不去的，说清哪一处。主人说「给我看出处」「看检查」，再贴出来。

## 5. 不说过程话
不说「我先拆一下结构」「我先看看规则」「对照原文」「重点不丢 ✅」「接下来我会……」；要讲的只有结果和要主人知道的事。

## 6. 交完
- 末尾不问「要不要接着……」；主人有改的地方会说。
- 主人说「哪里改一下」：只改那一处，重交受影响的文件，聊天里一句说改了什么。
- 演练模式下照常交，不写记忆。
