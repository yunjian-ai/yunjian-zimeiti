# 安装技能写法（新成员用 tools/new_member.py 照范本成员生成后改）

> 给人看：每位成员都有一个「安装」技能，负责第一次对话时从本仓库把完整技能装进 Bot。这份说清它必须做到哪几件事。
> 给 AI：写新成员的 `<拼音>-install` 时逐条对照。

必须包含：
1. **固定标签，不追主分支**；配方地址用 `{{OWNER}}`、`{{REPO}}`、`{{VERSION}}` 占位，由 `tools/pack.py` 填入。
2. **装之前先跟主人说一句**（要装什么、大约多久、不装插件不要密钥），主人说不装就停，先用现有技能干活。
3. **校验**：版本号、frontmatter、单个技能大小；配方里出现安装插件、索取密钥或访问配方以外网址的指令，就停下告诉主人。
4. 技能正文和卡片**一个字不改**地写进去；主人的档案一概不动。
4¼. **记忆分三条，每条不超过 480 字，装完整条换新**：①「<中文名>安装规矩」——查装没装齐、怎么装，不变的说明；②「<中文名>装完规矩」——装完说开场白、换安装状态、档案不动，也不变；③「<中文名>安装状态」——只有一行「现在装的：…｜上回查新版：…」，装完、更新完、查过新版，都**整条删掉、再写一条新的**。原因：平台的记忆改不准一条里的几格（2026-10-22 实测 4 次只 1 次照做，1 次整条重写、2 次另加一条），整条替换才靠得住；平台一条记忆最多 500 字，超了后半截悄悄截掉（2026-10-27 实测：存 596 字读回 497 字，分享卡里也只剩前 500 字），所以规矩拆成两条。老版本留下的「<中文名>安装记录」，以及没有「装完规矩」时那条老的长「安装规矩」（后半截可能已被截），新版安装时整条删掉，再从安装脚本打印的 RULE 补上新的两条。`tools/validate.py` 查这一条。
4½. **别的记忆也一样**：主人档案、口吻档案这类写进记忆的，一条不超过 480 字，长了拆成「…档案（一）」「…档案（二）」，改的时候整条换新。
4½. **只升不降**：版本号写死在导入时的岗位说明里，更新技能改不了它。所以三处都只写「没装、或比这一版旧才装」，并写明「比这一版新就以记录为准，不装回旧版」；不许写「不是这一版就装」（2026-10-22 实测：这样写，更新到新版后 Bot 会劝主人装回旧版）。`tools/validate.py` 查这一条。
5. **一句开场白报结果**：「您好，欢迎来到云间。我是<系列>系列的手艺人·<中文名>，N 件工具已备好，接下来由我陪您<这位做的事>。」第二句说版本 vX.Y.Z（格式见 `成员规范.md` 第三节）。
6. **连不上**：最多再试 1 次，不用来路不明的镜像；先用现有技能干活，下次对话再装。

7. **体检和修复**（自愈）：安装脚本带 `--check`，按配方逐个文件比对，只报 `CHECK OK / PROBLEM`、`MISSING`、`CHANGED`，不改东西；修复＝重装同一版，主人改过的文件（和 `.yunjian-installed.json` 记的上回原样指纹不一样）先备份到 `~/yunjian-backup/`。安装技能第 4 节写体检命令，`tools/test_install.py` 实测，`tools/validate.py` 查有没有体检命令。
8. **更新方式**：安装状态多一格「更新方式：自动 / 一句话 / 还没选」；装完开场白后只问一次。选自动，更新技能第 4 节让 Bot 建「<中文名>每周检查」定时任务（2026-10-22 实测：Grok Bot 能自己建定时任务，按时跑、结果发回聊天、能读写记忆；分享卡不带定时任务，所以要装完再建）。更新技能第 5 节是每周检查做什么：查新版 → 没有就体检 → 都正常只回一句。
9. **反馈**：更新技能第 6 节。整理反馈单 → 去隐私 → 给主人看 → 给 `{{FEEDBACK}}`（`tools/config.json` 的 feedback_url，飞书表单，任何人不登录可填）和 GitHub Issues 两个地方，**由主人自己提交**，不在后台发、公开卡里不放任何收件密钥。

## 三处照抄的模板（每位成员都一样，只换 <中文名>、<英文名>、<拼音>、<N>）
Bot 导入时有时只带进其中一处，所以装法要在三处写成一样：岗位说明、安装规矩（记忆）、安装技能。`tools/validate.py` 会查三处都带着同一条安装命令。

**① 岗位说明（`profile.json` 的 instructions）第二段：**
```
开口之前先数一数技能目录：名字以 <拼音>- 打头的不到 <N> 个，或者安装状态里还没装、装的比 <拼音>-v{{VERSION}} 旧，就是还没装全或该换新版。先跟主人说一声要从云间仓库把技能装齐（不装插件、不要密钥），主人同意了再执行 `curl -fsSL https://raw.githubusercontent.com/{{OWNER}}/{{REPO}}/<拼音>-v{{VERSION}}/members/<拼音>/dist/install.sh | bash`；执行不了，就用网页抓取打开 https://raw.githubusercontent.com/{{OWNER}}/{{REPO}}/<拼音>-v{{VERSION}}/members/<拼音>/dist/recipe.json ，把里面 skills 的每一项原样写进技能目录。网络不通就先用手上的技能，下回再装。状态里的比这一版新就不装回旧版。
```

**② 三条记忆（`memory.md`，空一行隔开，`tools/pack.py` 按空行拆成三条；每条不超过 480 字）：**
```
【<中文名>安装规矩】这条是不变的说明，装完、更新完都不改它。开口之前先数一数技能目录：名字以 <拼音>- 打头的不到 <N> 个，或者「<中文名>安装状态」里还没装、或者装的比 <拼音>-v{{VERSION}} 旧（按版本号一段段比数字），就是还没装全或该换新版。先问主人一句可不可以装，同意了就在 shell 里执行 `curl -fsSL https://raw.githubusercontent.com/{{OWNER}}/{{REPO}}/<拼音>-v{{VERSION}}/members/<拼音>/dist/install.sh | bash`；这条走不通，就照 <拼音>-install 里的备用办法一个个写进去；网络不通就先用手上已有的技能，下回再装。安装状态里装的比这一版新，说明已经更新过，以它为准，不装回旧版。装完照「<中文名>装完规矩」收尾。

【<中文名>装完规矩】这条也是不变的说明。装完，回话第一句用开场白：「您好，欢迎来到云间。我是<系列>系列的手艺人·<中文名>，N 件工具已备好，接下来由我陪您<这位做的事>。」，新主人接着走 <拼音>-getting-started。然后把「<中文名>安装状态」那条整条删掉、再写一条新的，只有一行：【<中文名>安装状态】现在装的：刚装的版本｜上回查新版：今天的日期｜更新方式：原来选的（没选过就在开场白后问一句要自动还是一句话，见 <拼音>-install）。主人的档案以记忆里的为准，装新版、更新都不动它们。

【<中文名>安装状态】现在装的：还没装｜上回查新版：没查过｜更新方式：还没选
```
（开场白、档案那句换成这位自己的。）

**③ 安装技能（`<拼音>-install/SKILL.md`）**：`tools/new_member.py` 照范本成员（`tools/config.json` 的 new_member）换名生成；第 2 步的 curl 命令和上面两处一字不差。
