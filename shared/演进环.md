# 演进环（收件箱 → 四选一 → 只局部改）

> 给人看：主人纠正一次就往规矩里加一条，规矩会越堆越多、前后打架。演进环的做法是：纠正先记进**收件箱**，再判**四选一**——新增、改旧的那条、作废旧的、不动；只改那一条，改完回归。这样越用越准，规矩却不越写越多。
> 给 AI：收到纠正、反馈、错题、新洞察，先照第二节写一条收件，跑 `python3 tools/danzi.py <收件箱文件>` 查格式，再照第三节判、改、验。格式正本 `shared/收件.schema.json`。

## 一、六步
1. **收**：主人纠正、用户反馈单、考试错题、干活中冒出的洞察，一律先记一条收件，不直接改正本。
2. **判**：四选一——**新增**（正本里确实没有）／**更新**（有一条，改它）／**作废**（旧的那条不对了：标「失效＋日期」，不删）／**不动**（已经有、或只是一次性的）。先在正本里搜同类，同类几条一起判、合成一类修。
3. **改**：只局部改判中的那一条，写出处和日期；**不许整篇重写**（整篇改写会把攒下的细节冲掉）。
4. **验**：跑相关考题回归＋预算闸。**回退规则**：常驻字数降了、回归通过率也降了，这一步撤回，换做法再来。
5. **发**：要随版本走的（成员技能、引擎规范），升版本、写 CHANGELOG；开发侧的规则、经验改完即生效。
6. **量**：下次体检看三个数——收件箱没判几条、正本条数、冷的几条。

## 二、收件条长什么样
```
### 收件 · <YYYY-MM-DD> · <来源：主人纠正／反馈单／错题／洞察>
- 原话：<一两句原话；长的写路径>
- 对应正本：<哪个文件哪一条；同类几处都列；没有写「无」>
- 第几次：<同类第几次>
- 判：<新增／更新／作废／不动>，<一句为什么>
- 改了哪：<哪个文件哪一条、改成什么；不动写为什么>
- 验：<回归、预算闸 ✅／❌／⚠️>
```
一条 ≤600 字。判完、验完，整条挪进同目录 `<年-月>.md` 留底，收件箱里只留没判完的。

## 三、放哪
| 哪一侧 | 收件箱 | 正本 |
|---|---|---|
| 运行侧（Bot） | 进度文件 `~/.yunjian/<拼音>/进度.md` 的「主人最近纠正了什么」——就是一级收件箱，不另建文件 | 技能、我的库、主人档案 |
| 开发侧 | 知识库 `演进环/收件箱.md` | 全局规则母版、记忆、经验笔记、成员技能、引擎规范 |

运行侧同类纠正到第 2 次，Bot 提醒主人交一张反馈单（去隐私），开发侧收进收件箱再判；Bot 自己只改主人的档案和我的库，不改技能。

## 四、规矩的升降
| 同类第几次 | 落到哪 |
|---|---|
| 1 | 进度文件「最近纠正」（开发侧：收件箱判「不动」或改经验） |
| 2 | 写进对应技能或经验笔记 |
| 3 | 能程序拦的进硬闸（检查脚本、validate）；拦不了才进原则 |

- **原则满 8 条**：要加一条，先合并或降一条。
- **降冷**：8 周（56 天）没触发、没用到的规矩和经验降到冷档——不删，挪进冷档文件，需要时召回；体检会列出来。
- **同一件事只留一个正本**：别处写「见某某」，不抄第二份；发现两处写法不一样，判「更新」一处、「作废」另一处。

## 五、节奏
每周体检一次（看第一节第 6 步的三个数）；每月把收件箱清空一次；每季度对照外面新出的做法看一次引擎自己要不要改——引擎也走这六步，升版本后各项目同步。
**越来越好用的标志**：写在字里的规矩越来越少、程序检查越来越多；收件条多了，正本条数不跟着涨。
